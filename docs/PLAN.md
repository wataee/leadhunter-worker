# LeadHunter: План работ по качеству лидов (feature/lead-quality)

## 1. Цель и контекст
Пользователь — видеомонтажёр-фрилансер (Казахстан). Цель — находить исключительно разовые и проектные заказы (ролики, YouTube, Reels/Shorts, подкасты, реклама, моушн, цветокор, тестовые задания, регулярный фриланс с оплатой за ролик/проект) и отсекать:
- Полный рабочий день, штат, офис, оклад, график 5/2, ТК, соцпакет, испытательный срок, HR/резюме.
- Вакансии, где монтаж упомянут вскользь (SMM, маркетолог, графический дизайнер).
- Предложения услуг от самих монтажёров («смонтирую вам ролик»).
- Рекламу курсов и инфобизнеса («нужен монтажер?» как лид-магнит).
- Строительный и промышленный монтаж.
- Устаревшие посты и дубликаты.

## 3. Этапы реализации

### Задача 1 (Приоритет 1). Трёхуровневый фильтр: разовые заказы вместо штата
1. **Скрипт воспроизведения дефектов (`scripts/reproduce-filter-defects.mjs`)**:
   - Воспроизвести пропуск штата («в штат, 5/2, оклад 150к», «full-time editor $3000/mo, 40 hrs/wk»).
   - Воспроизвести рекламу курсов («нужен монтажер? обучим с нуля»).
   - Воспроизвести ложные срабатывания от широких сигналов найма («ищу видеомонтажера» от лица монтажера).
   - Воспроизвести пропуск устаревших постов после перезапуска воркера.
2. **Размеченный датасет (`test/fixtures/leads.jsonl`)**:
   - 150+ примеров на русском, казахском и английском языках (реальные посты из кэша/логов + синтетические для редких классов).
   - Классы: `gig` (целевой), `fulltime`, `seller`, `course`, `other_profession`, `spam`.
   - Поля: `id`, `text`, `lang`, `label`, `source`, `confidence`, `notes`. Спорные случаи — в `test/fixtures/leads.disputed.json`.
3. **Трёхуровневая архитектура фильтра в `web/src/shared/`**:
   - **Уровень 1 (Hard Stops)**: Стоп-слова и регулярные выражения с границами слов `\b...\b` для штата/офиса/ТК/5-2/резюме/курсов/строительного монтажа.
   - **Уровень 2 (Weighted Scoring 0–100)**: Конфигурируемые веса в `web/src/shared/filter.config.json` (плюсы за разовость, фикс-прайс, дедлайн, ссылку на ТЗ, минус за штатность, учет автора).
   - **Уровень 3 (AI Fallback 40–60)**: Проверка пограничных случаев через `_shared/ai.ts` с кэшем по sha256 и лимитами.
   - Единый формат ответа: `{ isMatch, score, label, reasons: string[] }`.
4. **Синхронизация скоринга**:
   - Единый модуль используется в воркере (`server.js`), в Netlify-функциях бота (`tg-notify.ts`) и в клиенте (`vacanciesStore.ts`).
   - Настраиваемый порог для Telegram-уведомлений (высокий) и для ленты сайта.
5. **Обратная связь в Telegram (`👍 / 👎`)**:
   - Кнопки в `tg-notify.ts` (заменяют «Скрыть», сохраняя минимализм по `DESIGN_RULES.md`).
   - Обработка в `tg-callback.ts` с сохранением вердиктов.
   - Скрипт `scripts/tune-filter.mjs` для анализа обратной связи и рекомендации весов.
6. **Оценка качества (`scripts/eval-filter.mjs`)**:
   - Замер Precision и Recall до и после изменений. Цель: Precision $\ge 85\%$, Recall $\ge 80\%$.

### Задача 2 (Приоритет 2). Доставка и фильтрация Upwork в Telegram
1. **Тестовые фикстуры и воспроизведение**:
   - Фикстуры писем Upwork (single, digest, html, text).
   - Анализ точек потери заказов в `upwork-ingest.ts` и `upwork-email.ts`.
2. **Безопасность и авторизация**:
   - Строгая проверка `WEBHOOK_SECRET` (не менее 16 символов).
   - Логирование предупреждений при использовании fallback через query-параметр.
   - Обработка отсутствия токенов Telegram без молчаливого проглатывания (счётчики ошибок).
3. **Единый пайплайн Upwork**:
   - Парсинг $\to$ нормализация $\to$ англоязычный фильтр Задачи 1 $\to$ дедупликация $\to$ отправка в Telegram с кнопками $\to$ синхронизация с сайтом.
   - Честный расчет ROI без ложной уверенности при отсутствии данных клиента (пометка «неполные данные»).
4. **Хранение и метрики**:
   - Перевод хранения в Redis на безопасную модель (или хэш с TTL), исключающую потерю данных при параллельных запросах.
   - Счётчики полученных/отфильтрованных/отправленных лидов по источникам.
   - Алерт при отсутствии заказов более N часов (не чаще раза в сутки).

### Задача 3 (Приоритет 3). Чистка и расширение базы Telegram
1. **Анализ текущих 223 источников**:

   - Пересчет `qualityScore` на базе реальной доли подходящих постов.
2. **Поиск новых специализированных каналов**:
   - Поиск каналов и чатов видеомонтажа, YouTube, Reels, фриланса (KZ / RU / EN).

3. **Оптимизация поллера**:
   - Приоритезация по `gigRate` вместо слепого round-robin.
   - Использование `min_id` и сохранение `lastPolledId` в storage для предотвращения повторной обработки после рестарта.
4. **Автоматизация**:
   - Обновление GitHub Actions workflow `verify-sources.yml` для периодической переоценки и предложения PR.
